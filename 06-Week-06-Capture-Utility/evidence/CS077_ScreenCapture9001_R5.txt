🚀 1. OUR PROJECT – BUILD FOR YOUR OWN STORY

Our program, Screen Capture 9,001, is designed to capture screenshots of the computer screen and save them as PNG images.

We chose the context "Build for Your Own Story" because we wanted to create something that allows people to preserve important visual information before it disappears, changes or becomes difficult to prove.

For example, someone could capture an important online conversation, message or computer error before it gets deleted.

🇯🇵 2. DESIGN AND CONCEPT

We designed our application around the Japanese flag.

⚪ The white background represents the flag. 🔴 The red circle in the centre acts as our capture button. 🐉 Vegeta stands to the side as a decorative feature.

The user simply clicks the red circle to take a screenshot.

The name "Screen Capture 9,001" is a reference to Dragon Ball Z and Vegeta's famous power-level scouter.

We chose this name because we wanted our application to have its own identity rather than looking like an ordinary screenshot tool.

Our little bit of lore is that instead of detecting someone's power level, our application detects and captures what is happening on the screen!

⚙️ 3. CODE ORGANISATION

We organised our C# code using a MainWindow class and a separate ScreenCaptureService class.

MainWindow manages the interface and user interactions, while ScreenCaptureService handles the actual screenshot process.

This separates responsibilities and makes our code easier to understand, maintain and improve.

Our main methods include:

• btnCapture_Click() Runs when the user clicks the red capture button.

• CaptureScreenshot() Coordinates the screenshot process, plays the camera sound and displays a confirmation message.

• CaptureScreen() Captures the primary monitor and saves the image.

📦 4. IMPORTANT VARIABLES AND OBJECTS

• captureSound – A MediaPlayer object that plays the camera sound after a screenshot is taken.

• captureService – An object that accesses our screenshot functionality.

• screenBounds – Stores the dimensions and position of the primary monitor.

• screenshot – A Bitmap object that temporarily stores the captured image.

• graphics – Copies the screen contents into the bitmap.

• filename – Creates a filename using the current date and time.

• filePath – Stores the location where the screenshot is saved.

🛠️ 5. RESOURCE HANDLING

We used using statements for the Bitmap and Graphics objects so their resources are automatically released after the screenshot has been saved.

This helps prevent unnecessary memory usage.

We also used a MediaPlayer object to manage the camera sound and a try-catch statement to handle errors if the screenshot cannot be saved.

Our screenshots are saved in the user's Pictures folder using Environment.SpecialFolder.MyPictures, making them easier to locate later.
